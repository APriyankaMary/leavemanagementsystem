System Architecture & Notification Lifecycle

How multi-channel status updates flow seamlessly across In-App, Email, and ServiceNow.

Stage 1

📝 Leave Applied

Employee submits request via web portal. System saves state as PENDING_APPROVAL.

  • In-App: Immediate confirmation alert with sound chime.
  • Email: "Confirmation: Leave Request Submitted" sent to employee.
  • ServiceNow: Triggers sn_hr_leave.request.submitted event.
Stage 2

⏳ Pending Reminder

Automated reminder triggered when a request is waiting for manager review.

  • In-App: Badge reminder in employee & manager notification drawer.
  • Email: "Pending Review: Reminder" sent to employee & manager.
  • ServiceNow: Escalation reminder logged in HRSD case queue.
Stage 3A

✅ Leave Approved

Manager reviews and clicks Approve. Status changes to APPROVED.

  • In-App: Instant green push toast and permanent notification history entry.
  • Email: Branded approval email with calendar Out-of-Office advice.
  • ServiceNow: Case state updated to Closed Complete.
Stage 3B

❌ Leave Rejected

Manager rejects request with mandatory feedback reason. Status changes to REJECTED.

  • In-App: Red alert toast displaying reason for rejection.
  • Email: Formal rejection notification with manager remarks.
  • ServiceNow: Case closed as Rejected with audit reason.
Stage 4

⚪ Leave Cancelled

Employee cancels an approved or pending leave. Status updates to CANCELLED.

  • In-App: Cancellation receipt alert and balance restored.
  • Email: "Leave Cancelled" confirmation with freed balance details.
  • ServiceNow: HR case cancelled and calendar reservation released.
